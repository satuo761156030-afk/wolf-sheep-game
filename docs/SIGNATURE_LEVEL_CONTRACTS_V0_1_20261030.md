# 狼与幻羊｜三张标志性关卡的设计合约 v0.1
> 2026-10-30。配合 [3+32关总纲](./GAME_DESIGN_3PLUS32_V0_1_20261030.md)。**此文件约束地形/AI/可观察性与真正的胜利窗口，不是编造的已成功回放。** 具体坐标和路线必须由真实引擎截图、固定种子回放和试玩验证确定，不能因为文字看似合理就打 PASS。

## A. 正式23《好心办坏事》（甜品：利用职责）

### 最小空间拓扑
- 推荐9×9或11×11紧凑牧场，中间有可穿的两条通路，不许只有一条一格长廊。左侧偏近假羊可能活动的位置，右侧有真羊与其护卫，二者由守卫能走的通道连接。
- 初始真羊受可见守卫实际保护，而**假羊能够在狼按规则诱导后，沿自然逃路踩到可放置的陷阱**。开局不能让假羊自己必然中陷阱；玩家要判断站位与陷阱位置。
- 被困发生处到守卫的**可走路线**必须短到在当前受困窗口内真实赶得上。不得延长羊陷阱时长、停住守卫或让守卫瞬移只为演戏；先检查受困回合减少时机与守卫行动顺序。困难模式守卫也允许基于已感知事实选择不救。
- 守卫出发救援后，玩家须有一个合理窗口发现真羊**已不受实际守卫护盾保护**；真羊的安全感能短暂延续但被狼逼近会改变。这是游戏原有安全感语义的复用，不是给真羊人为“停留3回合”的脚本。
- 预留“守卫可能返程”带来的风险：玩家只能趁机设计捕捉，不能因为救援开始就获得免费通关。

### 目标体验路线（需在真实AI中证明，不是强制顺序）
1. 玩家发现假羊可以被陷阱影响；主动让假羊走向陷阱。
2. 被困羊的异常被守卫以合理视野/近距声音感知；守卫做出救援判断并开始逐格走向目标。可以出现“救援优先/追击优先”的真实冲突。
3. 玩家观察到原护卫位置空了，绕路或突击接近真羊；真羊可能慌张，改变捕猎路线。
4. 玩家最终因为**先前创造的守卫职责冲突**而成功抓真羊。

### 非诱救的备用赢法
- 绕后把守卫从盾位引走；或者用围栏/草地进行隔离后抓羊。备用路线不是同一个诱救剧本换个开场动作。

### 一票否决
- 被困目标是假羊时守卫自动不救、真羊时必救（AI偷看 real 标志）。
- 简单模式永远不救，困难模式必须刚好站在旁边才能救且地图无法抵达。
- 守卫视野外隔墙知道陷阱、救援瞬移、忽略贴身狼、两名守卫同时离岗而无警觉。
- 羊在陷阱内仅剩一个回合，守卫却须走四格；图上看着像能骗其实根本不行。
- 从开局等待即可不费力取胜，比主动发现玩法更划算。

## B. 正式26《请君入瓮》（甜品：反锁两个守卫）

### 最小空间拓扑（按门的连接关系，不拘具体坐标）
三块可达区域 A、B、C：A 是狼起始诱敌区；B 和 C 是羊群可到达的两片上层牧场。A↔B 通过门 G1，A↔C 通过门 G2，B↔C 通过门 G3；不增加会让围捕失效的隐藏边道。每个区域都不能只有1个格子，狼与两守卫不能天然卡死在G1/G2上。
- 两守卫在实际职责/追击反应下**有机会**被同一诱敌区 A 吸引，同时两扇出入口G1/G2可以分别关住；但狼需要有合法行动机会脱离 A，门不能跨地图操作。
- **三门都要起作用**：关闭G1与G2后，狼应能经G3走动于B/C，真羊仍有可捕获路线，而不是把自己也关死、或羊被隔在永远到不了的区域。
- 两守卫有路径规划与状态，封门后不得继续穿墙追狼；若门被挡住应寻找门、等待或放弃追逐，不能游戏故障；狼自身关闭门也花回合，门上有人不能关。

### 玩家可能自己发现的解法
- 有人选择分段引诱：先引一名守卫经G1，再用叫声/站位引第二名守卫进A，自己趁隙从G2到C，关G2，沿G3绕到B，关G1。
- 具体动作顺序不要求完全如上；需要真实引擎证明至少一条合理序列，且不利用开发者调试手段、守卫卡墙失智或无效回合。
- 不采取“锁两个守卫”的玩家，也可牵制一个、绕过一个后捕羊。
- **称得上甜品的条件**：玩家获得“我居然能反过来关住追我的人”的发现，而不是通关前弹窗直接教他怎么关。

### 一票否决
- G1/G2 无法正常关、守卫起始位置决定永远不进入A、狼逃到B后无法近门操作、实际拓扑有绕路让守卫瞬间回牧场。
- 所谓“困守卫”只有静态截图，AI没有真的追进来；或测试把两名守卫直接设置成困在A。

## C. 正式32《终夜围猎》（综合考试：对手也有计划）

### 核心空间
- 推荐最多11×11，双牧场+三条有意义的路线；2守卫，1真羊+少量假羊，1-3道门，局部换位，部分月影/草丛。不需要再加“第三守卫”、“全新终局专用能力”、“超长等待时间”来制造难。
- 初始布局必须让玩家能推理哪些位置受到实际守卫保护，而不是靠点击随机试错。
- 玩家至少有一次重要选择：守卫职责冲突（诱敌/救援/回防）或通路开关；当其中一种局势发生后，羊的安心/恐惧或局部换位改变后续计划。
- **围栏、幻羊、守卫AI联动要真实：**守卫被引开会改变护盾，羊察觉/换位必须符合局部和预兆规则，门关上会改变所有对象路径（包括守卫救援路径）；狼扑击不能跨墙/偷抓换位后的隐形目标。

### 三类不同的合理胜利策略（均需实际证明）
- **A 路线：空间控制**。先通过门与站位缩减有效逃路，再在羊真实可逃情况下截断其最优路线。
- **B 路线：注意力操纵**。利用草丛/嚎叫/月影引开主要守卫，在守卫回位前由另一条路接近真羊。
- **C 路线：职责冲突**。先制造假羊险情，诱出救援机会，再依据真羊是否受惊作出第二个决定并抓捕。
- 三条路线必须在**行动决策与对手响应上实质不同**，不是相同脚本更改开场两步。简单/困难要各有真实完整胜路；困难可让玩家需要更多判断，但不能依赖AI违规感知。
- **失败后应有调整机会**：战术失败不等于毫无征兆瞬间被杀；但玩家走到守卫正脸也不能获得免费豁免。

### 一票否决
- 玩家只要一直离羊7格外等待换位就能轻松通关；比正常围猎更好的策略是挂机。
- 设计师通过强制技能使用顺序或唯一高危路径制造难度。
- 只提高羊和守卫数量，没出现因果链；三条所谓胜路全靠同一个守卫卡墙漏洞。
- 终局视觉仍只是普通胜利弹窗；没有至少一次独特收尾表现（但先保证玩法通过）。

## D. 三关通用实测验收
- 生成并锁定用于复盘的关卡配置、地图截图、完整操作序列、种子、难度、回合状态、失败/胜利证据；可以自动化协助，但**实际游戏浏览器端至少完整播放**。
- 任何一条声称可实现的策略，应有“狼行动→守卫决策→羊响应→地图新格局”因果回放；拒绝仅记录最终PASS。
- 先用现有引擎制作可玩原型并证实普通羊过渡动画和教程弹窗不会妨碍操作，再调整细节；不允许把原型无法通关归因“玩家不够聪明”。
- 与旧 Bug 相关的回归以 Issues #1 / #2 为底线，不得在做地图时让守卫贴脸失效、陷阱无回合、换位完全消失、关门跨图、羊永远安心。
- 任何不满足本合约的关卡都可以**重设计**，不能仅靠硬编码获胜/脚本胜路伪造验收。

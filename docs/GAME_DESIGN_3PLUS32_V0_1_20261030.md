# 狼与幻羊｜3+32 正式关卡设计总纲 v0.1（进入制作的工作规格）
> 2026-10-30 · 基于v32.1 `b4bcd97` 的产品设计提案。**不是已实现的关卡、不是通过实测的解法，更不是全部32关经用户批准的最终地图**。设计团队/ Codex 必须按阶段落实并用真实游戏引擎、真实玩家反馈迭代。禁止把旧40配置重新排序充当设计完成。

## 0. 为什么这次重做
- 之前设计失败的根源不是“还不够难”，而是没有让玩家**利用自己观察到的规则，主动导演对手的行为**。旧版后期只是叠大地图、叠守卫；第16关双桥暗号比第20关更难，难度曲线失真。
- 首先让玩家理解真实规则，然后给其创造“原来还能这样用”的机会；**7场甜品关**穿插在压力关之间。甜品关不是教学、没有官方指定解法；失败不会因关卡设计而死局。
- **最终关是综合应用、不是全部技能点名签到**：观察守卫的职责、推理真羊、预判羊逃路、用门和陷阱布局、当计划被打乱时重组策略。
- 产品循环：看清局势 → 做出有代价的决定 → 对手依照可感知事实反应 → 玩家理解后调整 → 亲自获得战术性胜利。
- 不强制“首尾呼应”；只在剧情与机制真的匹配时考虑装饰性彩蛋。

## 1. 机制和体验的硬约束
1. **通用行为而非关卡剧本**：守卫救援要成为所有地图都适用的行为，羊的安全感、恐慌、换位、守卫协防、门操作、陷阱与嚎叫彼此有因果；禁止按关卡ID固定对手站位、指定路线、胜利条件特判。
2. **两类信息公平**：普通行走要有按 Sheep ID 的平滑位移动画，2×2两羊交错运动也能看清；魔法换位单独显示紫兆/换位效果，不可让逐帧动画泄露被交换后的隐藏真羊身份；困难AI不凭空看穿未发现的陷阱、狼或墙后羊。
3. **每个决定有代价**：关门花回合、嚎叫暴露位置、陷阱有有效期且诱敌并非每次成功、等待允许对方采取行动；不人为添加10回合必死计时器，也不默认羊一定沿设计师最喜欢的一条路。
4. **玩家不是技能打卡机**：任何正常策略抓真羊就通关。甜品策略是发现后爽，不是唯一解。对手不无脑、但会依职责犯合理错误。
5. **同一任务保留旧资产**：v32.1音效、UI、皮肤、设置、移动、存档、简单/困难、无尽及基线关卡不被盲删；正式3+32独立 ID、迁移旧记录后才进入正式编号。
6. **关卡顺序按真实试玩重排**：3关教程后，正式关1–8掌握追与截；9–16身份与幻象；17–24环境与守卫职责；25–32控制局势。难度不能只因图更大或守卫更多而增加。
7. **不提前揭晓甜品解法**：进关只允许自然环境叙述，机制首次登场有简短提示；旧机制重复出现不自动弹视频。赢后可以有有趣的小成就或特殊反馈，但不可提前剧透。
8. **避免制作伪成就**：不能只写“发现好心办坏事”文本却没有可执行AI与被救羊，不能只做一张截图/内部debug路径就宣布已可玩。

## 2. 三关教程（与32正式关严格分离）
- **T1 看见猎物**：第一眼依次聚焦可点狼（“这就是你”）、金圈真羊、无金圈假羊；让玩家亲自移动与等待；触控提示与实际按钮完全对应；可随时关闭引导。
- **T2 认清目标**：嗅觉得到**当前**真羊位置的临时快照，随后羊继续正常移动；玩家在最简单的两路场景里学会“线索会过期”，不把金圈误作永远追踪。
- **T3 追与堵**：真羊始终有至少两条合法逃路，但安心时玩家等待它可以不动；狼逼近时它会反应。**进T3立即同时开放扑击与陷阱**，让玩家自行任选追、堵、放陷阱；不要求用两项技能，不固定羊原地或围成死巷，直接抓真羊即胜。第三关结束有真实自主操作带来的过关感，而非技能测验。
- 教程、演示、聚光灯唯一Owner。按**真实第一次出现**（有对应地图对象/能力可用+正确交互时机）触发，不靠旧stage编号；机制卡必须真正展示或明确跳过才能标记seen，入队不得标记；已学过的可手动重播但不自动复播。
- 新关首见机制依次为：正式03高草、04守卫护盾、05嚎叫、07围栏门、09换位、10泥地、12风铃、13伪装守卫、17月影、18警报、21主动救援；实际首次出现与真实代码 unlock 必须一致。用户选择关卡跳跃时需识别是否真的首见，不生搬编号。

## 4. 七场甜品关的差异（不可做成相同的诱守卫变体）
- 06《你来追我呀》：逆转**追逐者/被追逐者**身份。被守卫追并不等于失败，而是改变它的岗位。不会靠守卫傻站实现。
- 11《换吧，我等的就是你》：逆转**被换位戏耍**的体验；玩家可以选择不打断换位，预判它带来的新位置。
- 15《狼不见了》：逆转**嚎叫会暴露狼**的弱点；玩家把动静留在假位置，真正的狼已经走远。
- 20《请羊出去》：逆转**堵出口才是战术**的直觉；开门反而把羊赶到可以截击的路上。
- 23《好心办坏事》：逆转**守卫保护羊**的职责；它主动救被困假羊，玩家利用撤防与真羊未立即失去安全感的窗口。守卫救援必须先以真实代码修成通用规则。
- 26《请君入瓮》：逆转**门是隔离狼的障碍**；玩家把两个追自己的守卫反锁在狼起始区域，但自己从第三门回到羊区。三门占位、关门消耗回合、守卫不能穿门；不要求唯一解。
- 30《借羊赶羊》：逆转**狼必须亲自追上真羊**；通过狼自身站位和羊群恐慌传递，把羊群推向有利位置，玩家成为场上节奏的导演。
- 节奏：大难题后穿插低压“我想到招了”的关卡，不能为了定额强做7关。若实测发现一关只有脚本能通关，应重新设计或删除那关的甜品标签，不以数量充数。

## 5. 最终关「终夜围猎」硬条件
- **不做超大型堆料地图**：推荐11×11以内的真实拓扑、双牧场三路线，每一条路线都要产生真实选择；最多两名守卫，真羊+合理数量的假羊，不以数量制造难度。
- 起局可以观察守卫职责、护盾区域和明显的地形；真羊位置有合理获取方式（非免费永久高亮）。局部换位必须预告；月影/可见线索必须可以影响路线选择。**不能强制每个技能都按一遍**。
- 试图用A计划引开守卫，会触发羊群重新选择安全位置；B计划以门封路可能让另一名守卫回防；C计划以假羊诱救可以抢到短窗口，但守卫可能拒救。失败计划不是必死，允许玩家应变。
- **最少3条可以被真实AI完成的不同思路**（路线不只更换第一步），每条在简单/困难实测；允许真实玩家发现第四条。低收益刷等待/远距离诱换位，不得比正常理解地图更容易通关。
- 需要实际录像/序列截图呈现玩家第一行动如何改变守卫、羊和后续路线；每个改变有可观察线索。终局通过仅凭关卡初始化或模拟解答不算。
- 最终胜利反馈应有真实终章演出（非普通弹窗改标题），但视听是锦上添花，玩法体验第一。

## 6. 制作顺序与验收门槛（必须持续交付真实玩法，不是一次性写完）
- **Phase A 技术与三关教学（Issue #2）**：先羊的移动可读性和演示错位，再做T1–T3，现有方向盘做拇指优化；全屏/移动不遮挡。**先让用户亲自玩三关；不允许顺手生成32张地图。**
- **Phase B 通用规则与甜品原型（Issue #1）**：加入守卫主动救援（简单/困难均可、非神视角、有职责冲突），**先证明《好心办坏事》《请君入瓮》真实AI下有至少一条精彩、可重复的赢法**。失败则修机制/地图，不写假脚本凑成功。
- **Phase C 正式01–16**：按此表每4关一组设计/造图/打通；每4关截图、通关路线、首见机制、负反馈；不能整包堆32关不让试玩。
- **Phase D 正式17–32**：同上；28与32必须至少两条/三条策略真实通关，7个甜品关要给出可复现的“惊喜行为”证据。
- **每一关必须交以下五项**：① 真实引擎地图截图；② 机制/对手行动因果链；③ 至少1条不作弊的完整通关；④ 备用赢法或证明并非极端唯一解；⑤ 玩家能否看懂、短时间能否操作和复玩。关卡出现假死/坐等换位最优/操作太繁琐→退回设计，不能只调血量/改难度标签。
